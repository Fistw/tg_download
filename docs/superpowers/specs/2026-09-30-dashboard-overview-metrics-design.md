# 概览页指标修复与磁盘用量设计

**日期：** 2026-09-30

**状态：** 设计已获用户确认，等待规范文档审阅

## 问题

概览页面上的下载、CPU 和内存数据均显示为 0。排查发现：

- `/api/dashboard/stats` 等接口能正常返回；监控数据库里的文件级下载、上传指标为空。
- Bot 转发视频只写入 `forwarded_video_batches`，当前概览统计没有合并这些批次。
- 服务器虚拟环境未安装 `psutil`，而系统指标函数在导入失败时静默返回 0。
- 概览用 `Promise.all` 同时加载四类数据；任一个请求失败会阻止所有结果更新。

本次同时在概览显示下载目录所在分区的磁盘容量和使用情况，避免下载分区接近满载时没有可见信号。

## 目标

1. 概览的下载统计同时反映现有文件级下载和 Bot 转发视频。
2. CPU、内存显示真实的系统指标；增加下载目录所在分区的已用、可用、总量及使用百分比。
3. 单个概览 API 请求失败时，其他成功返回的数据仍可展示。
4. 没有速度历史或历史记录时显示明确的空状态，不让空图表看起来像加载失败。

## 方案

### 后端统计

扩展 `/api/dashboard/stats` 的下载统计，从现有 `download_metrics` 和 `forwarded_video_batches` 汇总最近 24 小时数据。两者目前分别代表文件级任务和 Bot 转发视频批次，后端按视频项统计转发批次：

- `total`：文件级任务数，加转发批次中的 `total_videos`。
- `completed`：已完成文件级任务数，加转发批次中的 `downloaded_count`。
- `active`：活跃文件级任务数，加处于 `downloading` 批次中尚未完成或失败的视频数。
- `failed`：失败文件级任务数，加转发批次中的 `failed_count`。
- `avg_speed_kb_s`：沿用 `download_metrics` 中已有速度样本；转发批次不记录速度，不伪造速度值。

`failed` 是向现有响应对象新增的兼容字段。前端在下载卡片中展示失败数。

### 系统及磁盘指标

将 `psutil>=5.9` 声明为项目运行依赖，服务器与新安装环境都使用同一套 CPU 和内存采集实现。磁盘指标使用 Python 标准库 `shutil.disk_usage` 查询配置的 `download.output_dir` 所在分区，作为 `/api/dashboard/stats.system.disk` 的实时字段返回：

- `available`
- `total_bytes`
- `used_bytes`
- `free_bytes`
- `used_percent`

CPU、内存值允许为 `null`，避免采集不可用时伪装成 0。磁盘可用时 `available=true` 并返回上述容量值；不可用时 `available=false`，容量字段为 `null`。磁盘值在概览现有 10 秒轮询中实时刷新，不新增历史表或数据库迁移。后台历史采集继续写当前已有的 CPU、内存和连接字段。

### 前端

- 概览增加“磁盘用量”卡片，显示百分比、已用/总量、可用空间和进度条，标题说明统计的是下载目录所在分区。
- 下载统计卡片增加失败数。
- 下载/上传趋势在无速度样本时显示“暂无数据”；历史列表为空时显示空状态。
- 将统计、下载、上传和恢复记录的请求分别处理。成功请求更新对应区域；失败请求保留其他区域数据并显示可见的错误提示，刷新按钮仍可重试。

## 数据与错误处理

- 统计窗口统一使用最近 24 小时，与当前文件级下载、上传统计保持一致。
- 转发批次按 `created_at` 纳入统计，保留原始批次记录和现有 7 天清理策略。
- 磁盘采集以 `download.output_dir` 为路径；目录不存在或不可读取时，API 返回 `available=false` 和空容量字段，前端显示“不可用”，不得把失败误报成 0% 使用。
- `psutil` 采集或 API 调用失败时对应指标返回 `null`，前端显示“不可用”并保留其余成功指标。

## 验收

1. 给监控数据库加入文件级任务和转发批次样例后，统计 API 返回正确的总数、完成、活跃、失败和平均速度。
2. 空数据库返回有效零值，前端显示零值及合理空状态。
3. 安装项目依赖后，CPU 和内存不再因缺少 `psutil` 而恒为 0。
4. 磁盘统计对应下载目录所在分区，字节数和百分比与系统工具一致。
5. 模拟一个概览 API 返回错误，其他成功区域仍能更新，并显示局部错误提示。
6. 前端构建成功；部署后登录看板，确认概览数据、磁盘卡片和 `/health` 均正常。

## 不在范围内

- 为 Bot 转发视频补造下载速度历史。
- 磁盘使用历史曲线、阈值告警或自动清理设置界面。
- 上传任务数据模型或上传统计采集流程的改造。
